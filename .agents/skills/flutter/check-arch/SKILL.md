# Check Architecture

Verify that all files and folders from the base architecture are present and correctly structured.

## Arguments

The user invoked this skill with: `$ARGUMENTS`

- `--fix`: if passed, report problems and suggest how to resolve each one (do not auto-generate code)
- `--core-only`: if passed, only verify the `lib/core/` folder

---

## Instructions

### Step 0 — Prepare checklist

Use `TodoWrite` to create tasks tracking verification progress:
1. Core — constants, environments, extensions, icons, routes
2. Core — services/api
3. Core — services/storage and logger
4. Core — services injector
5. Domain and Data
6. Presentation — blocs
7. Presentation — screens and widgets
8. Bootstrap (main) and assets
9. Packages (design_system, gse_localization)
10. Final report

### Step 1 — Detect project root

Find `pubspec.yaml` in the current directory. Extract the `name:` field to use as the package prefix in imports. Note the root path.

```
### Core — [✅ COMPLETE | ❌ INCOMPLETE]

### Domain & Data — [✅ COMPLETE | ❌ INCOMPLETE | — skipped]
...

### Presentation — [✅ COMPLETE | ❌ INCOMPLETE | — skipped]
...

### Bootstrap & Assets — [✅ COMPLETE | ❌ INCOMPLETE | — skipped]
...

### Packages — [✅ COMPLETE | ❌ INCOMPLETE | — skipped]
...

### Missing files
(Only if there are missing items)
❌ lib/path/to/file.dart

### Final verdict
[✅ ARCHITECTURE COMPLETE — The project is ready to start adding features]
[❌ ARCHITECTURE INCOMPLETE — Resolve the issues above before continuing]
```

If `--fix` was passed, add a **How to fix** section with specific steps for each missing or incomplete file:
- If it is a generated file (`env_config.dart`, `app_icon_name.dart`, `.freezed.dart`): indicate the tool command that generates it
- If it is an architecture file: indicate what it must contain at minimum

**Verdict rules:**
- `core/` is always mandatory — any missing item in core = INCOMPLETE
- If `--core-only`: verdict is based only on core
- If not `--core-only`: all groups must be complete for a COMPLETE verdict
